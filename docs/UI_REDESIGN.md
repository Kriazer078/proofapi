# ProofAPI — UX/UI redesign

Дата проверки: 1 октября 2026. Направление: **«Проверяемый реестр»**. Визуальная спецификация: [DESIGN_DIRECTION.md](../DESIGN_DIRECTION.md).

## Продукт и приоритеты

ProofAPI фиксирует отпечатки входа, ответа ИИ и метаданных в последовательном журнале. Главный результат — сертификат с публичной ссылкой и возможностью независимой проверки. Сертификат подтверждает целостность записи; он не подтверждает правильность ответа ИИ, фактическое использование заявленной модели или юридическую силу результата.

Основные роли: разработчик, подключающий HTTP API; специалист, создающий и отправляющий сертификат; получатель ссылки, проверяющий запись без аккаунта. Отдельный рабочий кабинет в текущем frontend отсутствует. Новая навигация ведёт только к существующим сценариям.

Порядок внимания: вердикт → объект и время → выполненные проверки → ответ ИИ → evidence и технические детали. Частота использования страниц не измерена аналитикой; приоритет сертификата определён из сценария продукта, а не выдан за результат пользовательского исследования.

## Аудит исходного интерфейса

| Information architecture | Маркетинговые обещания кабинета перемешаны с публичной проверкой | Получатель ссылки вынужден разбираться в подключении сервиса | Разделены обзор, создание, проверка, журнал и API-документация; публичная шапка облегчена |

| Visual hierarchy | Метрики, печать, карточки и результат ИИ конкурируют с вердиктом | Трудно понять, что подтверждено | Вердикт первым; риск ИИ ниже проверок; scope виден без раскрытия подробностей |

| Responsive | Поле проверки сжимается в вертикальном flex; полная навигация переполняет планшет | Ввод неудобен, часть действий исчезает | Минимальная высота полей; меню до 1024 px; статус/дата журнала сгруппированы на mobile |
| Accessibility | Ошибки, focus и destructive flow несогласованы | Клавиатурный пользователь теряет контекст | Label/error associations, skip link, visible focus, live status, AlertDialog с отменой и focus trap |
| Consistency | Главная, формы, сертификат, таблица и автономный HTML говорят разными визуальными языками | Снижается доверие при переходах | Общие цвета, компактные компоненты, одна иерархия; standalone-verifier согласован без внешних зависимостей |
| Trust/copy | FAQ обещает закрытый документ, хотя evidence доступен по ссылке; hash-only выглядит как проверка содержимого | Интерфейс обещает больше, чем система доказывает | Предупреждение перед upload; точные подписи режима отпечатков, testnet и локальной симуляции |

### AI-slop: что было устранено

Убраны карточки внутри карточек, крупные скругления, декоративное вращение/появление печати, blur в overlays и избыточное выделение тарифов. Сохранены только функциональные контейнеры: документ, форма, таблица и пример. Печать оставлена как идентичность продукта и дублируется текстовым вердиктом. Badges используются для реальных состояний журнала.

Нет оснований утверждать, что в каждом исходном экране были gradients, neon или blobs: это запреты направления, а не выдуманные находки аудита.

## Canonical screen и компонентная система

Canonical screen — `/proof/[id]`: это результат, который отправляют клиенту. Его поверхности, отступы, типографика и порядок чтения перенесены в остальные экраны. Sidebar не добавлен: существующие публичные сценарии его не требуют.

- Оболочка: ширина 1180 px, header 56 px, gutters 16/24 px; документ до 960 px, формы до 640 px.
- Typography: display 32–36 px; page-title 24/32; section-title 18/24; card-title 14/20; body 15/22; secondary/label 13/20; caption 12/16; table 14/20.
- Spacing: 4/8/12/16/20/24/32/40/48 px. Большие размеры используются для секций обзора, не для строк данных.
- Radius: 4/6/8 px. Старые XL-алиасы приведены к 8 px для совместимости; новых oversized-контейнеров нет.
- Buttons: 36 px default, 32 px compact, 40/44 px large; на mobile и coarse pointer targets минимум 44 px, длинные подписи переносятся.
- Inputs: 40 px desktop, минимум 44 px mobile. Select и file input сохраняют общие label/focus/error conventions.
- Shadows: только elevation overlays. Основные поверхности без теней.
- Motion: короткий feedback и индикатор фактической операции; reduced-motion отключает движение. Нет искусственного прогресса.
- Icons: Lucide; брендовая печать — специализированный SVG с уникальными ID, без постоянной анимации.

## Реализованные сценарии

Обновлены обзор, upload, проверка ссылки, сертификат, журнал, API-документация, privacy/terms, 404, ошибка страницы, loading журнала и независимый verifier.

Upload имеет отдельные выбор и подтверждение отправки, проверку формата/размера, видимое предупреждение о доступности evidence. Сертификат различает checking, verified, changed, pending и unavailable. Pending не выдаёт отсутствие проверки за изменение данных. Первой записи соответствует «Начало журнала», последующим — проверка связи с предыдущей записью.

Журнал фильтруется и отображается по 25 записей. Это пагинация представления; сервер по-прежнему проводит аудит всей цепочки. Названия и ссылки чужих сертификатов исключаются сервером до передачи клиенту. Backend-пагинация и оптимизация RPC не добавлялись.

Удаление сохранено, но теперь требует отдельного AlertDialog. Проверена отмена, Escape, начальный фокус и замыкание Tab; необратимое удаление через UI не выполнялось.

## Final polish / reduction

Устранены несогласованные радиусы, высоты полей, переполнение tablet header, влияние системной тёмной темы на отдельные светлые primitives, дублирующие scope-подписи и ложные названия проверок hash-only. Убраны декоративный risk gauge на сертификате, blur, вращение печати, карточки тарифов и искусственная пошаговая загрузка. Не добавлены несуществующий кабинет, аватары, боковая навигация, декоративные графики или новые бизнес-сценарии.

## Границы проверки

Live end-to-end Solana devnet и реальный Google Gemini не запускались. Их backend-контракты покрыты существующими тестами; это не заменяет проверку реальной интеграции перед выпуском. WCAG-сертификация и полный screen-reader audit не проводились; проверены семантика, keyboard flow, связность ошибок, размеры targets и контраст. Аватары и профили не применимы: таких экранов в текущем frontend нет.

Это UI-реализация для существующей беты. Коммерческий запуск по-прежнему зависит от предусмотренных продуктом инфраструктуры, рабочих интеграций и условий эксплуатации; redesign не выдаёт запланированные тарифы и кабинет за реализованные функции. Deployment не выполнялся. Production smoke test выявил отсутствующий `NEXTAUTH_SECRET` в исходном локальном окружении: для проверки использован временный секрет процесса и `NEXTAUTH_URL=http://localhost:3000`. Для реального запуска требуется собственная production-конфигурация; `.env` не изменён.


## Уточнение главной по обратной связи пользователя

Главная возвращена к формату тёмного продуктового лендинга. Первый экран объясняет пользу простым языком, показывает пример сертификата и предлагает создание или проверку. Добавлен последовательный сценарий «юрист → клиент → проверка спустя время». Сохранены демо подмены, отраслевые примеры, API, планируемые тарифы, FAQ и контакты.

Тема задаётся контейнером `SiteShell` только на `/`, поэтому переходы не меняют светлые рабочие экраны. Общие компоненты используют те же семантические переменные; совместимые aliases переопределены внутри тёмного контекста. Свечения, градиенты и анимированный декор отсутствуют.

Проверены главная на 390 и 1440 px, изменение/восстановление данных в демо и переход к светлой странице `/verify` с возвратом на тёмную главную. Горизонтального переполнения нет. Это локальное изменение; опубликованный сайт не обновлялся.

Итоговая проверка уточнённого лендинга: `npm run build`, `npm run typecheck` и `git diff --check` прошли. Собранная production-версия проверена локально, в том числе тёмное мобильное меню. Дополнительно проверена ширина 320 px без переполнения.


## Единая тёмная тема и навигация — последнее уточнение

По следующей обратной связи пользователя прежнее разделение на тёмную главную и светлые рабочие страницы отменено. Корневые токены теперь тёмные для всех страниц, портальных диалогов, меню, уведомлений и независимого verifier. Ранее приведённая таблица светлого контраста относится к предыдущей итерации. Новая навигация сохраняет порядок ссылок; на мобильном раскрывается под шапкой, имеет aria-expanded/controls, закрывается по выбору ссылки или Escape с возвратом фокуса. Тарифы объединены в сравнительный блок с выровненными действиями.

Проверка новой темы: desktop 1440 px, mobile 320/390 px; документация → проверка, мобильная навигация → журнал, тарифы и форма создания. Без переполнения страницы. Контраст secondary/surface 8.60:1, muted/subtle 6.16:1, success/status-surface 6.22:1, warning 7.66:1, error 5.99:1, input-border/surface 3.10:1. `npm run typecheck` и 14 тестов verifier-html/encoding прошли. Референсы структуры: [OpenRouter Developers](https://openrouter.ai/developers), [OpenAI API Docs](https://developers.openai.com/api/docs).
